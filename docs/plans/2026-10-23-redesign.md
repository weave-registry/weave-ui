# Plan: the console redesign — a dark ops console with side navigation

**Intent:** [docs/intent/2026-10-23-redesign.md](../intent/2026-10-23-redesign.md) ("same crappy UI, I asked you to
redesign it" → "build it"). **Source of truth for the look:** the approved mockup — Home (`Main.dc.html`), Work and
Machines, approved 2026-10-22. weave-ui keeps no ADR directory; this plan is the decision record for the new visual
system (the Phase 2 plan was the record for the parity port).

## Decisions

1. **One theme, dark.** The design system (`tokens/brand.json`: "colorScheme: dark only") and the mockup are dark.
   `tokens/colors_and_type.css` takes the mockup palette and `bun run fix:tokens` regenerates the JSON; `weave.css`
   defines the same palette once in `:root` — the light theme and the `prefers-color-scheme` copy go. The 4.5:1
   floor stays on every documented text pair (test/tokens.test.ts), and the one pair Phase 2 carried below it
   (white on the dark `--bad`) is fixed rather than exempted.

   | Role | Value | Role | Value |
   |---|---|---|---|
   | ground `--bg` | #0E1014 | text `--fg` | #E7E9ED |
   | sidebar / top bar `--side` | #12151A | muted `--muted` | #A3AAB6 |
   | panel `--surface` | #161A20 | faint `--faint` | #7D8592 |
   | raised / hover `--sunken` | #1E232B | lines `--line` / `--line-soft` | #262B33 / #1F242C |
   | needs you (fill / text) | #F2A93B / #F7C46F | broken (fill / text) | #FF7A70 / #FF9A92 |
   | healthy (fill / text) | #5FD08A / #7FDCA2 | in progress, links (fill / text) | #6AA8FF / #8DBBFF |

2. **Fonts: the system stack, no webfont files.** `Inter, system-ui, …` and `"JetBrains Mono", ui-monospace, …`:
   Inter and JetBrains Mono are used where the operator's machine has them and the system faces otherwise. Not
   vendored, because the size budget (assets ≤ 160 KiB) had about 4 KiB of headroom before this work and one Inter
   weight as woff2 is ~23 KiB (four weights plus two mono weights would be ~150 KiB). Nothing loads from a CDN.

3. **The shell: a left sidebar on every page** (`src/layout.ts`). The weave mark; a network chip (health dot,
   verdict, weave version); the nav in two groups — Operate: Home, Work, Factory, Audit · Fleet: Machines, Team,
   Control — each with an icon (a CSS mask from a `data:` SVG keyed on `data-key`, so no markup per icon; the CSP
   allows `img-src data:`) and a live count or dot; at the bottom the yolo state and time left, a spend bar, and
   Halt as its CLI command (ADR-0245 §3 — the console credential may not halt or resume). A thin top bar: a
   breadcrumb and a search box (a plain GET form to `/audit?find=…`, the record search weave already serves). On a
   phone the sidebar stacks above the content.

4. **Where the sidebar's live values come from.** The page shells are static, so the values come from a view model.
   Home's view model (`HomeViewModel`: the harness facts plus the Work view) carries every one of them. The `home`
   template appends out-of-band fragments to its section — `#side-net`, `#side-foot`, `#nav-meta-<key>`, and for the
   Machines page `#host-telemetry` and `#model-drift` — swapped with `hx-swap-oob="innerHTML"` so each target keeps its
   own element. On every page but Home the shell carries a hidden `#view-home` slot that loads `/ui/f/home` once (the
   fragment then polls itself, as on Home) and the stylesheet keeps it hidden; targets a page does not show sit in a
   hidden sink, so no out-of-band fragment ever lacks a target. This is weave's own pattern: an action already answers
   with every view in its refresh list, and each lands where its target is.

5. **The visual system** (`assets-src/weave.css`): panels (12px radius, 1px line, no shadow), KPI tiles, dense list
   rows (tag · one-line title · one-line reason · inline buttons), pills, filter chips, dots, `<meter>` bars (never a
   width style), tables, the health banner, buttons (light primary, outline default, red-outline danger). The old
   component classes (`.card`, `.row`, `.badge`, `.status`, `.section`, `.btn`) are restyled in the same system, so a
   page not yet re-laid-out still reads as the new console. The build minifies the stylesheet (comments and
   whitespace) so the source can stay readable inside the size budget.

6. **Behaviour stays in `assets-src/app.js`, bound by `data-` attributes**: the Needs-you filter chips
   (`[data-filter-scope]`, `[data-filter]`, rows `[data-cat]`), remembered across polls. Nothing inline.

## PRs, files and order

Each PR: the failing tests for a file are committed, then that file is changed through `hexa do run --model
claude-opus-5-5 --file <file> --evidence "bun run typecheck && bun run test && bun run check:tokens"` (the tokens file
also runs `bun run fix:tokens` first), one file at a time, each run leaving every gate green.

**(a) tokens + stylesheet + sidebar shell + Home**
1. `tokens/colors_and_type.css` (+ regenerated `brand.json`, `theme.json`) — the palette; `tokens/tools/check-tokens.mjs`
   records the font decision and checks `--faint`.
2. `scripts/build.ts` — minify `weave.css` into `dist/`.
3. `assets-src/weave.css` — the new system, the shell, Home; old components restyled.
4. `src/layout.ts` — the sidebar shell, the hidden Home feed and sink.
5. `src/templates/home.ts` — Home: banner, KPI strip, Needs-you rows with chips, side column, the out-of-band
   sidebar fragments; Working now, Done recently, Decided for you and Ask weave kept, in the new rows and panels.
6. `assets-src/app.js` — filter chips.
7. `assets-src/favicon.svg` — the amber wave mark.

**(b) Work + Machines** — `src/templates/work.ts`, `src/templates/machines.ts`, `src/templates/fleet.ts`, stylesheet
additions.

**(c) the other pages** — Factory, Team, Control, Task, Audit, error: page heads and panels in the new system.

## Tests that change, and why

- `test/tokens.test.ts`: reads the one dark `:root` palette instead of a light block plus a dark copy; same pairs, same
  4.5:1 floor, no exemption; adds "weave.css's palette is the tokens' palette".
- `test/shells.test.ts`: the nav assertion pinned a top bar of text-only links in weave's flat order; it now pins the
  sidebar's two groups, each core page once, the current page marked, and the Home feed.
- `test/home.test.ts`, later `work`, `machines`, `review` markup assertions: rewritten for the new markup. Every safety
  assertion stays: no `/ui/a/fleet` post, halt and resume as CLI text, escaping (shape test untouched), CSP lint
  (untouched), purity (untouched), the size budget (untouched).

## Risks

- **Size budget** (assets ≤ 160 KiB, ~4 KiB headroom): icons as CSS masks, not markup; the stylesheet minified at
  build; the shells kept lean. `test/size.test.ts` is the proof.
- **Hidden Home on every page** doubles Home's poll on non-Home pages (one fragment every 10 s). Accepted for live
  sidebar counts without changing weave; recorded here.
- **Hostile corpus**: new out-of-band ids are fixed strings; data reaches markup only through the `html` tag.

## Proof

Per PR: `bun run typecheck`, `bun run test`, `bun run check:tokens`, weave's loader proof
(`node --import tsx scripts/weave-loader-proof.ts <weave checkout>`), and screenshots of the changed pages at 1440 px

Of the 18 verbs, 9 work correctly when every value arrives as a string. Five fail or do the wrong thing because the handler checks `=== true` (yolo, chat reset, fleetDecide, rolloutDecide, releaseMergeDecide). Three can't be sent from a flat form at all (plan accept, role define) or go wrong on an empty field (budget). The worst problem: the three fleet-plugin decide verbs record a **deny** when they get `approve:"true"`, with no error, and the deny is final.

Two other findings you didn't ask about:
- **Wrong examples.** The `DECIDE` example `{key, approve:true}` (`src/domain/console-api.ts:124`) is wrong for all four verbs that use it. fleetDecide and rolloutDecide take `id`, releaseMergeDecide takes `version`+`sha`, and factoryDecide takes `{key, label}` with no `approve` at all. The `factory` example `{issue:1, stage:"triage"}` is also refused, because `title` is required (`src/domain/factory-trigger.ts:80`).
- **role's soft failure looks like success.** When a role definition fails validation, `role` returns `{ok:false, errors}` instead of throwing. `act()` (`src/adapters/primary/sse-surface.ts:552-563`) wraps that as a success and shows the team view; the errors never appear.

Handler order: core verbs run inline in `onEvent` (`src/cli.ts:8513`) before any plugin command is tried (`dispatchGatewayCommand`, ~`src/cli.ts:8800`). So the `agent` handler at `src/cli.ts:8667` always wins, and the console plugin's `agent` handler (`src/composition/plugins/console/index.ts:237`) is never reached for `{agent:{…}}`.

### Not string-safe, and the smallest fix for each

1. **yolo, chat (`reset`), fleetDecide, rolloutDecide, releaseMergeDecide** (boolean `=== true` checks).
   - **Fix:** give each `ActionRoute` a typed field list, like `ViewParam.numeric` (`src/domain/console-api.ts:55`). For example `booleans: ["on","off","status","reset","approve"]`. `formBody` (`src/domain/console-api.ts:299`) would then turn `"true"`/`"false"` into booleans for those fields only.
   - **Why not convert everywhere:** a blanket rule would also change chat `text:"true"` and a `title:"true"`.
   - **Why not also convert all-digit values:** every numeric consumer already calls `Number()`. A blanket digit rule would break string fields that can be all digits: grant/plan/rollout ids, factory `title` (refused if not a string, `src/domain/factory-trigger.ts:79`) and release `version`.
   - **Defence in depth:** have the three fleet handlers refuse a non-boolean `approve` instead of reading it as false.
2. **budget, factory (`url`/`repo`)** (empty fields): `formBody` should **drop empty-string fields**. Then `usd` is missing, `Number(undefined)` is NaN, and it's refused instead of meaning "no ceiling". An empty `url=` no longer fails the factory check either.
3. **plan accept and role define** (need arrays or nested objects): a flat `Record<string,string>` can't express these. Smallest fix: those two forms post `application/json`, which `/ui/a` already accepts (`src/adapters/primary/sse-surface.ts:681`), e.g. with htmx's json-enc. The alternative is teaching `formBody` repeated keys and dotted paths.
4. **Examples (not a type problem):** update the `CONSOLE_ACTIONS` examples so the bad-body hint is correct. Use `factory: {issue, stage, title}`, `factoryDecide: {key, label}`, `fleetDecide`/`rolloutDecide: {id, approve}`, `releaseMergeDecide: {version, sha, approve}` and `rolloutAbort: {id}`.
5. **refresh:** add `control` to `yolo` and `fleet`.

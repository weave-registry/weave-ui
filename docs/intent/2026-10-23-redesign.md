# Intent: redesign the console, do not port it

What the operator asked for, in their words, in order:

- 2026-10-10: "we need a better console ui"
- 2026-10-12: "an effective dashboard"
- 2026-10-22, on opening weave-ui after Phase 2 (a parity port of weave's old console): "same crappy UI, I asked you to redesign it"
- 2026-10-22, on the redesign mockup (dark ops console: KPI strip, Needs-you list with inline buttons, pipeline
  board, host cards): "much better, also add side navigation"
- 2026-10-22, on the mockup with the side navigation: "build it"

## What that means here

Phase 2 kept the old look on purpose (parity first). This work changes the look on purpose. A page that still reads
like the old console — light cards, sentences where a number would do, a top tab bar — has not been redesigned.

The mockup is the source of truth for structure, styling and data mapping (Home, Work, Machines). The other pages
(Factory, Team, Control, Task, Audit) move into the same shell and visual system without new layouts.

## What does not change

- Templates stay pure functions from weave's view contract to escaped HTML; the purity scan, the hostile-corpus shape
  test, the handler lint, the CSP, the size budget and weave's loader proof all hold.
- weave is not changed. Only data the vendored contract (1.2) already carries is shown; a mockup element with no data
  is derived from what exists or dropped, and the plan lists each one.
- Halt and resume stay on the command line (weave ADR-0245 §3).
